# 온보딩 재설계안 (v2.1 목표)

작성: 2026-07-23 · 전제: 팀 공유는 참여 포함 구독 전용(현행 유지), 공유 입구는 팀 초대코드 단일화

---

## 1. 설계 원칙

- **첫 화면에서 사용자 유형을 나눈다.** 처음 쓰는 사람 / 재설치한 사람 / 초대받은 사람은 필요한 것이 완전히 다르다. (이번 재설치 복구 사고의 교훈: 복구 경로가 온보딩에 없어서 설정을 뒤져야 했음)
- **필수만 온보딩에서 받는다.** 카메라·알림 권한, 구독 안내는 필요한 순간에 해당 기능이 처리 (기존 게이트 재사용).
- **기존 코드 최대 재사용.** 새로 만드는 화면은 분기 화면 하나뿐. 나머지는 기존 함수 호출로 연결.

## 2. 전체 흐름

```
[0. 환영 + 분기]
 ├─ 🆕 처음 시작해요      → A1 업종 → A2 내 이름 → A3 업체정보(스킵가능) → A4 자동백업 선택 → [완료]
 ├─ ☁️ 쓰던 데이터 복구   → B1 복구 방법 선택(로컬/서버) → 복구 실행 → B2 확인 → [완료]
 └─ 💌 초대코드가 있어요  → C1 구독 안내 → C2 로그인 → C3 닉네임 → C4 코드 입력 → A1 업종부터 합류
```

## 3. 화면별 상세

### 0. 환영 + 분기 (신규)
앱 아이콘 + "현장 매니저" + 한 줄 소개. 버튼 3개:
- **🆕 처음 시작해요**
- **☁️ 쓰던 데이터가 있어요** — 부제: "재설치·기기 변경 시 백업에서 복구"
- **💌 초대코드가 있어요** — 부제: "동료에게 초대받았다면"

### 경로 A — 처음 시작

| 단계 | 내용 | 재사용 |
|---|---|---|
| A1 업종 | 대분류→소분류 선택. 보고서 제목·호칭 자동 설정 | 기존 setup 슬라이드의 업종 파트 그대로 |
| A2 내 이름 ★신규 | "작업자 이름으로 사용돼요" 1칸 필수. 저장: `WorkerCombo.record(이름)` → ac_worker_names 주입 + coNick 보관(추후 로그인 시 닉네임으로 승격) | worker_combo.js |
| A3 업체정보 | 업체명·전화 (나머지는 설정에서). **[건너뛰기]** 허용 | 기존 setup 슬라이드 축소 |
| A4 자동백업 | 기존 옵트인 팝업 내용을 슬라이드로: 장점 + "저장공간 최대 2배" 경고 + [사용하기/사용 안 함]. 선택을 auto_backup_enabled에 기록 → 별도 팝업 안 뜸 | auto_backup.js maybeAskOptIn 문구 |
| 완료 | "시작하기" + 하단 한 줄: "동료와 일정을 같이 보려면 설정 → 팀 공유 (구독 기능)" | |

★ A2가 중요한 이유: 작업자 기본값이 "닉네임(로그인 필요) → 최근 사용 이름" 순인데, 최초 설치+비로그인은 둘 다 없어 매 저장마다 차단됨. 온보딩에서 이름 하나 받으면 해결.

### 경로 B — 재설치 복구

**B1 복구 방법 선택** (버튼 2개 + 설명):
- **📁 백업 폴더에서 복원** (무료·사진 포함) → `importBackupFromPicker()` 재사용. 자동백업 폴더를 지정해뒀던 사용자용.
- **☁️ 서버에서 복구** (구독) → 로그인 → `CloudBackup.checkAndOfferRestore()` 명시 호출. 텍스트+이번달 사진 우선, 나머지는 온디맨드.
- 하단: "둘 다 해당 없으면 [처음부터 시작] " → 경로 A로.

**B2 확인**: 복구 건수 표시. 업종·업체정보·이름은 backups/{uid} pull 또는 로컬 백업에 이미 있으므로 **A1~A3 스킵**, 비어 있는 항목만 있으면 해당 슬라이드만 노출. 자동백업(A4)은 항상 물음(재설치로 키가 초기화되므로).

### 경로 C — 초대코드

| 단계 | 내용 | 재사용 |
|---|---|---|
| C1 구독 안내 | "팀 공유는 구독 기능이에요 (베이직 월 9,900원~). 팀 참여에도 구독이 필요해요" — 코드 입력 전에 미리 고지(설치 후 결제 요구에 놀라지 않게) | subscription.js 플랜표 |
| C2 로그인 | 구글 로그인 | cloud.js |
| C3 닉네임 | 팀에 표시될 이름 입력 → `CloudShare.saveMyProfile` + `WorkerCombo.record` (A2 겸용) | |
| C4 코드 입력 | 6자리 입력 → `CloudTeams.joinByCode(code)`. 게이트가 미구독이면 구독 화면으로 자연 연결. 성공 시 "○○팀 참여! 팀원 일정이 달력에 함께 보이고 팀 채팅방이 열려요" | teams.js |
| 이후 | A1 업종부터 합류 (A2는 C3에서 완료됐으므로 스킵) | |

## 4. 충돌 방지 (코드 수정 포인트)

1. **auto_backup.js `maybeAskOptIn`**: `ac_onboarding_done_v1` 미완료면 보류 (온보딩 A4가 대신 기록). 온보딩 완료 후에도 키가 없을 때만 팝업 (기존 사용자 업데이트 케이스).
2. **cloud_backup.js `checkAndOfferRestore`**: 온보딩 진행 중엔 자동 팝업 보류 — 경로 B에서 명시 호출로만. 온보딩 완료 상태(기존 사용자)는 현행 유지.
3. **뒤로가기**: 각 슬라이드 → 이전 슬라이드, 분기 화면에서는 무시(종료 아님).
4. **ONBOARDING_DONE_KEY 버전업**: `ac_onboarding_done_v1` → `v2`. 단, v1 완료자(기존 사용자)는 v2 온보딩을 다시 보지 않도록 v1 키 있으면 v2도 완료 처리.
5. 기존 "사용법 안내" 슬라이드(6종)는 현행대로 온보딩 제외, 설정 → 사용법 다시 보기 유지.

## 5. 구현 순서 제안

1. 분기 화면(0) + 슬라이드 라우팅 구조 변경 (onboarding.js)
2. A2 내 이름 슬라이드 + ac_worker_names 주입
3. A4 자동백업 슬라이드 + maybeAskOptIn 게이트
4. 경로 B (backup.js·cloud_backup.js 연결 + checkAndOfferRestore 게이트)
5. 경로 C (로그인·닉네임·joinByCode 연결)
6. DONE_KEY v2 마이그레이션 + 뒤로가기 처리
7. sw 버전업 + 시나리오별 테스트 (신규/재설치-로컬/재설치-서버/초대-구독/초대-미구독)
