# 팀 공유(여러 명) — 게시해야 할 Firestore / Storage 규칙

팀 공유는 `users/{uid}.teamIds` 배열의 **교집합(hasAny)** 으로 "같은 팀이면 서로 읽기 허용"을 판정한다.
아래 내용을 **현재 규칙에 병합**해서 게시해야 팀원 간 일정·사진이 보인다.

## 1) Firestore 규칙

`rules_version = '2';` 의 `match /databases/{database}/documents {` 안에 추가/수정:

```
// ── 헬퍼: 나와 ownerUid 가 같은 팀에 속하는가 ──
function sameTeam(ownerUid) {
  return request.auth != null && (
    request.auth.uid == ownerUid ||
    (
      exists(/databases/$(database)/documents/users/$(request.auth.uid)) &&
      exists(/databases/$(database)/documents/users/$(ownerUid)) &&
      ('teamIds' in get(/databases/$(database)/documents/users/$(request.auth.uid)).data) &&
      ('teamIds' in get(/databases/$(database)/documents/users/$(ownerUid)).data) &&
      get(/databases/$(database)/documents/users/$(request.auth.uid)).data.teamIds
        .hasAny(get(/databases/$(database)/documents/users/$(ownerUid)).data.teamIds)
    )
  );
}

// ── 팀 문서 ──
match /teams/{teamId} {
  allow read:   if request.auth != null;   // 초대코드 조회 + 멤버 표시
  allow create: if request.auth != null
                && request.resource.data.owner == request.auth.uid
                && request.auth.uid in request.resource.data.members;
  // 참여/나가기: 팀장·이름 불변이면 허용(본인이 members 에 자신 추가/제거)
  allow update: if request.auth != null && (
                  resource.data.owner == request.auth.uid ||
                  (request.resource.data.owner == resource.data.owner &&
                   request.resource.data.name  == resource.data.name)
                );
  allow delete: if request.auth != null && resource.data.owner == request.auth.uid;
}
```

그리고 **기존 `schedules/{uid}` 읽기 규칙**에 팀 조건을 OR 로 추가한다. 예:

```
match /schedules/{uid}/{document=**} {
  // 기존: 본인 || 공유수락 상대  → 여기에 || sameTeam(uid) 추가
  allow read:  if request.auth.uid == uid
                || <기존 공유 조건>
                || sameTeam(uid);
  allow write: if request.auth.uid == uid || <기존 공유 쓰기 조건>;
}
```

`users/{uid}` 는 본인 write 가 이미 허용돼 있으면 `teamIds` 저장은 그대로 동작한다.

## 2) Storage 규칙 (공유 사진)

`sharedPhotos/{ownerUid}/...` 읽기에 팀 조건 추가. Storage 규칙은 Firestore 를 조회할 수 있다:

```
match /sharedPhotos/{ownerUid}/{allPaths=**} {
  allow write: if request.auth != null && request.auth.uid == ownerUid
               || <기존 공유작업자 쓰기 조건>;   // 상대가 보태는 add_ 사진
  allow read:  if request.auth != null && (
                 request.auth.uid == ownerUid ||
                 <기존 공유 조건> ||
                 firestore.get(/databases/(default)/documents/users/$(request.auth.uid)).data.teamIds
                   .hasAny(firestore.get(/databases/(default)/documents/users/$(ownerUid)).data.teamIds)
               );
}
```

## 참고 / 주의
- 팀 update 규칙은 "이름·팀장 불변" 조건만 걸어 팀원이 서로의 이름 등을 못 바꾸게 한다. 다만 팀원이 다른 팀원을 members 에서 뺄 수도 있는 느슨함이 있다(소규모 신뢰 팀 가정, 기존 1:1 공유와 동일한 신뢰 수준).
- `teamIds` 미설정 사용자는 `'teamIds' in ...` 가드로 오류 없이 통과.
- 규칙 게시 전에는 팀을 만들어도 팀원 데이터가 "권한 없음"으로 안 보인다. 반드시 게시할 것.
